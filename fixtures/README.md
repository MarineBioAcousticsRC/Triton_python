# Fixture corpus

Three directories, three different kinds of trust:

| Directory | What it is | Committed? |
|---|---|---|
| `generated/` | Synthetic files from `tools/make_fixtures.py`. Small, deterministic, cover the format matrix exhaustively. | **Yes** (~2.3 MB) |
| `real/` | Real deployment files contributed by the team. Cover what synthetic files cannot: actual recorder quirks. | **No** — gitignored |
| `reference/` | MATLAB ground truth from `tools/matlab/dump_reference.m`. | **Yes** |

`reference/` is committed deliberately: it lets the parity suite run on a machine with no MATLAB
licence, which most contributors will not have.

---

## Regenerating `generated/`

```bash
python tools/make_fixtures.py
python -m pytest tests/test_fixture_integrity.py
```

Output must be byte-identical every time — the manifest records a SHA-256 per file and the tests
check it. The generator uses `numpy.random.RandomState` rather than `default_rng` because NEP 19
guarantees the former's stream is stable across numpy versions forever; verified identical under
numpy 1.26.2 and 2.5.1.

## What `generated/` covers

| Fixture | Exercises |
|---|---|
| `xwav_v1_cont_1ch_16b_10k` | baseline |
| `xwav_v1_duty_1ch_16b_10k` | duty cycle: byte-contiguous, time-discontinuous; `readseg` splice; delimiter lines |
| `xwav_v1_ticks_1ch_16b_10k` | millisecond (`ticks`) start times |
| `xwav_v1_cont_4ch_16b_10k` | the other sector geometry (`blksz` 248 vs 250) |
| `xwav_v1_cont_1ch_16b_200k` | real HARP rate — the file that breaks float-datenum timing |
| `xwav_v2_cont_1ch_16b_10k` | v2 header: per-channel `drate`/`dt`, different subchunk-size formula |
| `xwav_v1_cont_1ch_32b_10k` | 32-bit *(see open question below)* |
| `xwav_v1_fakefs_1ch_16b` | `fmt ` rate ≠ raw-file table rate |
| `xwav_v1_gain4_1ch_16b_10k` | `gain` ≠ 1 |
| `wav_110130-084500_*` | plain wav, filename-timestamp pattern 1 |
| `wav_20110130_084500_2ch_*` | PAMGuard filename pattern, 2 channels |
| `wav_110130084500_1ch_24b_*` | 24-bit, SoundTrap filename pattern |

`python tools/make_fixtures.py --list` prints the same table with the full rationale per file.

## What we still need from the team: `real/`

Synthetic fixtures prove we implemented the *spec*. Real files prove we implemented *reality* —
they are the ones that carry the header quirks, clock glitches, and vendor deviations that
accumulated over twenty years of deployments. **The port is not trustworthy without a few.**

Please drop small files (ideally trimmed to < 50 MB each) into `fixtures/real/` and add a line to
`fixtures/real/MANIFEST.md` saying where each came from. Most valuable, in order:

1. **A real HARP `.x.wav`** — any deployment, any rate. Trim to a handful of raw files if large.
2. **A duty-cycled `.x.wav`** from a real deployment, ideally one whose gaps are irregular.
3. **The matching `.ltsa`** for either of the above, generated by the current MATLAB Triton.
4. **A v2-header `.x.wav`**, if any exist in the archive — nobody is sure how widely v2 was used,
   and the answer decides how serious the `io/ioReadXWAVHeader` v2 bug is.
5. **A 32-bit `.x.wav`** — needed to settle the open question below.
6. **An `.ltsa` of version 1, 2, or 3** — the writer only emits v4, so older files are the only
   way to test the v1–v3 read paths, and they must exist somewhere in the archive.
7. **A file that a previous Triton version choked on**, if anyone remembers one. Bug-compatible is
   the goal.

24-bit x.wav is *not* on this list: confirmed with the team that none exist — the archive is all
16-bit. (24-bit plain wav does occur and is covered synthetically.)

### Open questions these files would settle

- **32-bit `AudioFormat`.** `wrxwavhd.m:107` writes `AudioFormat = 3` (IEEE float) for 32-bit,
  but `readseg.m:100` reads `int32`. One is wrong. The synthetic fixture currently writes
  `AudioFormat = 1` with int32 samples; a real 32-bit file decides it.
- **`blksz` for non-16-bit data.** `ck_ltsaparams.m:50` hard-codes the 16-bit assumption, so
  `write_length` bookkeeping is questionable for 32-bit.
- **Channel counts other than 1 and 4.** Triton's sector geometry only defines those two. Do
  2- or 8-channel x.wav files exist in the archive?
- **How common are v2-header files?** See item 4.

Status of all open questions is tracked in [HANDOFF.md §6](../HANDOFF.md).

## Generating `reference/`

On a machine with MATLAB and Triton-master:

```matlab
addpath('D:\Code\Triton-master')
addpath('D:\Code\Triton_python\tools\matlab')
cd('D:\Code\Triton_python')

make_ltsa_fixture          % builds the .ltsa fixtures (one Save dialog each -- see its help)
dump_reference             % writes fixtures/reference/
```

No Triton GUI is started; `tr_headless_handles.m` supplies the handful of `HANDLES` that core
functions touch, so `readseg`, `check_time`, `mkspecgram` and `read_ltsadata` run for real rather
than being re-implemented in the dump script.

Re-run `dump_reference` and commit the result whenever the MATLAB side changes. The dump records
the MATLAB version and toolbox list in `_environment.json`; numeric output can shift between
releases and we want to know when it does.
